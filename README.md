# GGFC V3.25.20 · 계산 일관성 및 추가 파울

## 적용 방법

1. 관리자 화면에서 기존 JSON 데이터를 백업하세요.
2. V3.25.19 사용자는 `ggfc-record_V3.25.20_UPDATE_FROM_3.25.19.zip`을 풀어 같은 경로에 덮어쓰세요. assets 폴더 구조를 유지하세요.
3. 이전 버전 사용자는 `ggfc-record_V3.25.20_LIGHT_FULL_32files.zip`을 사용하세요. 운영 중인 firebase-config.js와 database.rules.json은 유지하세요. 두 파일은 이번 변경 대상이 아닙니다.
4. 배포 후 강력 새로고침하여 화면의 V3.25.20 표시를 확인하세요.
5. 관리자 데이터 관리에서 J열이 **추가 파울**인 최신 통합 Excel을 다시 업로드하고 저장 완료를 확인하세요. 프로그램 교체만으로 기존 DB의 구양식 파울을 추가 파울로 해석하지 않습니다.
6. 데이터 관리의 검증 안내에서 경기 충돌·출석 명단 누락 여부를 확인하세요.

운영 GitHub/Firebase에는 자동 배포하지 않았습니다. 소스 패키지에는 사용자 Excel, 테스트 선수, 로컬 선수 사진을 포함하지 않습니다.

## 변경 1 · SoccerBee 축별 측정 유효성

PAC·DRI·DEF·PHY 각각에 유효한 측정값이 있는지 판정합니다. 없는 값을 0 또는 내부 평균 77.5로 만들지 않습니다. 축의 일부 항목만 있으면 유효한 항목들의 가중치를 합계로 나누어 계산합니다. 그 축의 유효 항목이 전혀 없으면 직전 유효 측정 초기값을 유지하며, 최초부터 미측정이면 관리자 설정의 Provisional 값(기본 68)을 사용합니다. 초기값 전용 화면은 미측정 축을 —로 표시합니다.

축별 측정일을 유지합니다. 최근 행이 PAC만 측정한 행이라도 이전 DRI·DEF·PHY의 유효 측정값을 잃지 않습니다. 일부만 측정된 선수는 SB 일부로 표시합니다. 측정이 없는 축의 경기 성장분은 유지됩니다.

## 변경 2 · 모든 계산에 공통 검증 경기 적용

날짜·대회 계열·라운드·경기번호·양 팀이 같은 경기를 공통으로 묶습니다. 홈/원정 순서가 반대여도 정렬하여 비교합니다. 중복 ID의 같은 선수 수치는 한 번만 계산합니다. 다른 경기번호의 실제 경기는 별도 경기로 유지합니다.

중복 대진의 점수·파울·선수 기록이 서로 다르거나 같은 ID가 여러 대진을 가리키면 임의로 큰 값을 택하지 않고 해당 경기를 계산에서 보류합니다. 관리자 검증 안내와 공통 경고로 확인할 수 있습니다. JSON 원본은 남겨두며, 충돌 상태에서는 Excel 내보내기를 막아 누락 파일이 만들어지지 않도록 했습니다. 원본 Excel/JSON을 확인해 수정한 뒤 재업로드하세요.

통합 Excel에 완전히 같은 팀 행이 반복되면 한 번 반영합니다. 같은 경기·팀 행인데 내용이 다르면 업로드를 중단하고 이전 DB를 유지합니다. 선수 누적기록·능력치·팀기록·커플/듀오·역대기록·상세기록 등은 공통 검증 결과를 사용합니다.

## 변경 3 · 활동 증거와 공식 참석 구분

팀별 기록지에 양수 유효슛·키패스·수비성공·선방이 있고 날짜·라운드·경기번호·팀·선수가 명확히 연결되면, 선수1~15 누락 상태라도 활동을 인정하여 결석 감점을 방지합니다. 소속팀 불일치·반대팀 출석·경기 연결 모호함은 자동 인정하지 않습니다. 모두 0이거나 빈칸인 행도 참여 증거로 인정하지 않습니다.

활동 항목 자체의 능력치 반영은 유지하지만 공식 출전수·참석률·출석 성장 가산·경기 승점은 자동으로 부여하지 않습니다. 관리자 화면의 출석 명단 누락 안내에 따라 선수1~15를 보완한 후 반영됩니다. 능력치 현황의 참여R은 활동 증거를 포함하므로 공식 참석 수와 다를 수 있습니다.

## 변경 4 · 첫 측정에도 경기 성장분 보존

내부 계산을 측정 초기값, 경기 성장 누적분, 재측정 변화 누적분으로 분리했습니다. 각 축의 첫 측정일에는 초기값만 교체하고 그날 이전의 경기 성장분을 유지합니다. 측정 전 날짜로 소급 적용하지 않습니다.

이후 같은 축을 재측정하면 `(새 평가값 − 직전 유효 평가값) × 재측정 배율`을 적용합니다. 기본 배율은 기존대로 0.5이며 관리자 설정을 따릅니다. 측정값이 내려가면 재측정 변화도 음수가 됩니다. 점수 상·하한과 기존 FORM 규칙은 유지합니다.

## 변경 5 · 개인파울 + 추가 파울

**해당 경기 팀파울 = 해당 팀 개인파울 합계 + 해당 팀 추가 파울**

- 예: 개인파울 2회 + 추가 파울 3회 = 팀파울 5회.
- 추가 파울 빈칸과 0은 모두 0회입니다. 음수·소수·숫자가 아닌 값은 업로드 오류로 안내합니다.
- 추가 파울은 팀 통계와 팀파울 순위에만 반영하며 특정 선수 DEF를 감점하지 않습니다.
- 개인파울은 기존 개인 기록과 DEF 감점 규칙을 유지합니다.
- 구양식 파울/파울수/팀파울은 기존 호환 규칙으로 읽습니다. 새 양식 업로드 시 합산 규칙으로 전환됩니다.
- Excel 내보내기는 팀파울 총합이 아닌 추가 파울만 J열에 기록합니다. 구양식 자료를 내보낼 때는 기존 적용 팀파울에서 개인파울을 뺀 잔여값을 추가 파울로 저장하여 합계를 보존합니다.

## 검증 및 범위

첨부 `DB GGFC_통합_기록지_역대기록(2).xlsx`의 270경기를 읽었습니다. 개인파울 합계 22회, 추가 파울 합계 0회, 적용 팀파울 합계 22회입니다. 실제 Excel 내보내기/재업로드를 2회 반복해 경기 수와 팀파울 합계가 유지됨을 확인했습니다.

부분 측정, 첫 측정 성장 보존, 재측정 배율, 중복 경기, 홈/원정 반전, 충돌 보류, 출석 누락 활동 증거, 잘못된 팀 연결, 추가 파울의 개인 감점 제외 및 구양식 호환을 별도 예제 데이터로 검증했습니다. 첨부 Excel에는 SoccerBee 시트가 없어 SoccerBee 관련 검증에는 통제된 예제 측정값을 사용했습니다.

기존 All-Time Records의 2019~2025 보관 및 2026년 이후 경기기록 가산 기능은 유지합니다. 과거 통합값에 2026년 이후분을 수동으로 더하지 마세요. 우승 기록 자동 추론은 추가하지 않았습니다.
