## 어떤 파일을 올리나요?

- **현재 V3.25.6이면 `UPDATE_FROM_3.25.6.zip`만 적용합니다.** 변경된 7개 파일입니다.
- 설치 파일이 섞였거나 전체본이 필요하면 `FULL_84files.zip`을 사용합니다. 두 ZIP을 모두 적용할 필요는 없습니다.
- 파일명은 기존처럼 `ggfc-app.js` 등 고정 이름을 유지합니다. 구버전 이름의 파일을 새로 만들지 않습니다.
- 현재 `firebase-config.js`, `database.rules.json`은 그대로 유지하세요. 이번 변경에는 Firebase 설정·보안 규칙 변경이 필요 없습니다. FULL에 포함된 두 파일도 V3.25.6과 동일합니다.
- 이 파일은 업데이트 패키지입니다. GitHub 배포와 서버 DB 업로드는 자동으로 수행하지 않았습니다.

### GitHub 웹 적용 순서

1. 현재 저장소를 Code → Download ZIP으로 백업합니다. 관리자에서 현재 DB도 JSON으로 내려받습니다.
2. 업데이트 ZIP을 PC에서 압축 해제합니다.
3. GitHub 저장소 최상위에서 Add file → Upload files를 엽니다.
4. `index.html`, `mobile.html`, `README.md`, `assets` 폴더를 함께 올립니다. **ZIP 자체를 올리지 말고 폴더 경로를 유지합니다.**
5. Commit changes 후 Pages 배포가 완료되면 새로고침하여 **V3.25.7**을 확인합니다. 이전 화면이면 Ctrl+F5로 다시 불러옵니다.
6. 관리자에서 팀명이 추가된 통합 엑셀을 업로드합니다. 연결 확인은 **능력치 운영 안내 → 팀별 기록지**에서 확인합니다.
7. 관리자에서 **유지할 전체 측정 이력이 들어 있는 사커비 엑셀**을 업로드합니다. 공유 저장 완료를 확인합니다.
8. 데이터 관리 → 선수카드 등급 조건에서 등급별 디자인·조건을 확인하고, 변경 선수 미리보기 → 등급 기준·디자인 저장을 누릅니다.

## 1. 사커비 업로드: 엑셀 전체와 동기화

이번 버전부터 합치기가 아닌 **전체 교체**입니다. 엑셀에서 빠진 선수·날짜·경기순번의 측정은 DB에서도 제거합니다. 수정된 측정은 새 값으로 교체합니다. 유지할 과거 측정도 반드시 엑셀 안에 포함하세요. 프로그램이 사용자의 PC 엑셀을 실시간 감시하는 것은 아니며, **다시 업로드할 때** 반영합니다.

- 양식 헤더는 있고 측정 행이 없는 엑셀을 올리면 사커비 DB를 비웁니다.
- 잘못된 양식·날짜·숫자·선수명·충돌하는 중복 측정이 있으면 업로드 전체를 취소하고 이전 DB를 유지합니다.
- 선수명은 기존 선수명단·출전 DB와 정규화 매칭합니다. 유사한 이름을 임의로 합치지 않습니다.
- 같은 선수·날짜·경기순번의 동일 행은 한 번만 반영합니다. 여러 사커비 시트가 있으면 인식 가능한 시트 전체를 함께 반영합니다.
- 삭제 후 측정 이력, 사커비 초기값, 능력치 계산, 그래프는 남아 있는 기록으로 다시 계산합니다. 경기기록 자체는 삭제하지 않습니다.

## 2. 선수카드 상세 상자와 관리자 초기값

- **선수 기록 / CAREER FRAME · ACHIEVEMENTS / 능력치 변화 / 사커비 측정기록**의 제목을 눌러 개별적으로 펼치고 접습니다.
- 처음에는 접힌 상태입니다. 마지막 펼침 상태는 해당 브라우저에 저장하며 다른 회원의 화면 설정은 바꾸지 않습니다.
- Team 로고·선수카드·육각 그래프·OVR 그래프의 기존 배치는 유지합니다.
- Player ratings의 **SOCCERBEE ONLY · 사커비 초기값**은 관리자에게만 표시하고 제목으로 펼칩니다. 로그아웃하면 즉시 숨깁니다.

## 3. 팀별 기록지의 팀명

헤더 예시:
`날짜, 대회, 반기, 라운드, 경기번호, 팀명, 이름, 유효슛, 키패스, 수비성공, 선방`

열 위치와 무관하게 `팀명`, `팀`, `소속팀`을 인식합니다. 날짜·라운드·경기번호·대회 구분·이름으로 후보 경기를 찾고 **입력한 팀의 실제 출전 명단**과 대조합니다. 팀명이 잘못됐거나 그 팀에서 출전한 기록이 없으면 확인 필요 목록에 남기고 계산에서 제외합니다.

팀명이 없는 구양식은 실제 출전 경기·팀이 한 건으로 확정될 때만 연결합니다. 여러 팀으로 연결될 수 있으면 추측하지 않습니다. 구양식과 새 양식이 같은 출전에 중복 연결되면 값이 같은 경우 한 번만 집계하고, 다르면 두 기록 모두 확인 대상으로 분리합니다.

빈칸은 미기록, 0은 명시적으로 기록한 0회입니다. 선방은 팀별 기록지의 입력값을 우선하며 기존 선방과 합산하지 않습니다. 통합 엑셀 내보내기에도 팀명을 포함합니다.

## 4. 메뉴와 팀별 득점

왼쪽 메뉴:
**Team squad → Record Stories → Overview → Team stats → Player stats → Player ratings → Player Analysis**

Match Calendar는 Overview의 버튼으로 이동하며 기존 달력 기능을 유지합니다.

Team stats의 조회 구간 주요 득점은 **각 득점 행에 저장된 당시 팀** 기준입니다. 선수가 A팀에서 2골, 이적 후 B팀에서 3골이면 A팀 2골·B팀 3골로 표시합니다. 함께 표시되는 출석도 해당 팀의 출전 경기만 중복 없이 셉니다. 구간 필터를 벗어난 득점과 자책골·베네핏은 개인 주요 득점에 포함하지 않습니다.

## 5. 등급별 카드 디자인: 8단계

요청에 나열된 이름은 8개이므로 아래 8단계로 구성했습니다. 등급은 장식이며 OVR·능력치를 올리지 않습니다. 현재 또는 조회 기준일까지의 통산 출전·득점·도움·선방·MOM·승리로 계산합니다.

| 등급 | 출전 | 득점 | 도움 | 선방 | MOM | 승리 | 기본 디자인 |
|---|---:|---:|---:|---:|---:|---:|---|
| IRON · 아이언 | — | — | — | — | — | — | 클래식 |
| BRONZE · 브론즈 | 20 | 10 | 10 | 40 | 2 | 10 | 클래식·브론즈 색상 |
| SILVER · 실버 | 50 | 25 | 25 | 100 | 5 | 25 | 스타디움 실드 |
| GOLD · 골드 | 100 | 50 | 50 | 200 | 10 | 50 | 아우룸 로렐 |
| PLATINUM · 플래티넘 | 125 | 62 | 62 | 275 | 13 | 62 | 네온 실드 |
| DIAMOND · 다이아 | 150 | 75 | 75 | 350 | 17 | 75 | 다이아몬드 크라운 |
| MASTER · 마스터 | 175 | 87 | 87 | 425 | 21 | 87 | 루비 스트라이크 |
| CHALLENGE · 챌린지 | 200 | 100 | 100 | 500 | 25 | 100 | 로열 사파이어 |

- 기본은 각 등급의 6개 조건 중 **하나 이상** 충족입니다. 관리자가 1~6개로 바꿀 수 있습니다.
- 각 조건값과 필요한 조건 수는 상위 등급일수록 같거나 크게 설정합니다. 같은 기준이면 충족한 가장 높은 등급을 적용합니다.
- 8개 등급마다 기존 7종 디자인 중 하나를 선택합니다. 같은 디자인을 여러 등급에서 사용할 수 있습니다.
- **디자인 미리보기** 또는 아래 카드 디자인 상자에서 등급·스타일을 선택합니다. 미리보기는 실제 설정을 바꾸지 않습니다.
- **변경 선수 미리보기**는 기준일의 승급·하향·디자인만 변경되는 선수를 함께 보여 줍니다.
- **등급 기준·디자인 저장**으로 모든 등급의 조건과 디자인을 함께 적용합니다.
- 기록 추가·정정·삭제 또는 과거 날짜 조회 시 등급과 디자인은 자동으로 다시 계산합니다. 이전에 한 번 달성한 최고 등급을 영구 고정하는 방식은 아닙니다.

### 기존 관리자 설정 호환

기존 BRONZE·SILVER·GOLD 조건은 유지하며 LEGEND 조건·필요 조건 수는 CHALLENGE로 이어받습니다. 새 PLATINUM·DIAMOND·MASTER 조건은 **기존 GOLD와 LEGEND 사이를 4등분해 내림**합니다. 새 중간 등급의 필요 조건 수는 기존 LEGEND 조건 수를 사용합니다. 따라서 위 표는 기본값이며 사용자 지정 기준이 있으면 관리자 화면의 값이 실제 적용값입니다.

기존 NORMAL은 IRON입니다. 기존 공통 카드 디자인 설정은 IRON에 이어받고 다른 등급은 위 기본 디자인을 적용합니다. 등급별 디자인을 지정하면 그 설정을 우선합니다. 이전 설정은 읽을 때 임의로 덮어쓰지 않으며 관리자가 저장하면 새 8단계 구조로 저장합니다.
