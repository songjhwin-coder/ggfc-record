# GGFC DUO TYPE — 20종 계산식·판정·UI 설계

적용 버전: V3.22.0 / 판정 규칙: v1

## 목적과 적용 범위

CHEMISTRY MAP의 연결선을 클릭하면 두 선수의 경기기록, 선수능력치, SoccerBee, 실제 동행 성적을 조합해 Main·Sub 유형을 표시합니다. 기존 프로그램의 남색·파란색·진한 민트 디자인을 사용합니다. 별명은 기록에서 추정한 경기 스타일이며 OVR, 선수카드 승급 또는 원본 DB를 변경하지 않습니다.

초기 임계값은 설계값입니다. 실제 GGFC 전체 데이터의 유형 분포를 통계적으로 검증하거나 보정한 값은 아닙니다. 판정 규칙은 `assets/ggfc-duo-v3.22.0.js`에 있으며 이번 버전에는 DUO 규칙 관리자 편집 기능을 포함하지 않습니다.

## 1. 비교 범위와 원자료

- 지도의 대회·연도 선택을 따릅니다. 시즌은 기존 지도와 동일하게 달력 연도입니다.
- 각 시즌에서 5경기 이상 유효 출전한 선수를 비교 대상으로 삼습니다. 지표별 유효 측정 선수가 4명 이상이어야 해당 백분위를 계산합니다.
- 전체 연도에서는 각 연도의 백분위를 먼저 계산하고, 선수별 시즌 출전수로 가중평균합니다. 원자료를 여러 시즌에 걸쳐 한꺼번에 순위화하지 않습니다.
- 출전은 경기 ID·선수 단위로 중복 제거합니다. 같은 경기에서 양 팀에 동시에 등록된 선수 기록은 제외합니다. 기존 입단일·스쿼드 유효성 규칙도 따릅니다.
- 골·도움은 해당 선수의 유효 출전 경기와 소속 팀에 연결된 기록입니다. 시즌에 도움 필드가 전혀 없으면 도움과 공격포인트는 미측정으로 둡니다. 도움 필드가 있는 시즌에서는 득점 이벤트표에 없는 선수의 도움을 0으로 해석합니다.
- 참석률은 기간별 스쿼드의 해당 팀 경기수 대비 출전율입니다. 스쿼드가 없는 경기는 해당 시즌 실제 출전 팀을 대체 기준으로 사용하고, 입단일 이전 경기를 제외합니다. 최대 100%입니다.
- 능력치는 선택 시즌의 마지막 경기일까지 기존 능력치 계산기로 조회한 PAC/SHO/PAS/DRI/DEF/PHY입니다. 능력치 기능이 꺼져 있으면 제외합니다.
- SoccerBee는 같은 시즌의 마지막 경기일까지 입력된 값 중 지표별 최신 유효 측정을 사용합니다. 시즌 후 측정값을 과거 판정에 사용하지 않습니다. 서로 다른 지표가 서로 다른 측정일에서 선택될 수 있습니다.
- 파울은 본인 출전 경기의 80% 이상에 명시적인 숫자(0 포함)가 있어야 사용합니다. 파울률 분모는 파울이 명시된 경기수입니다. 전체 연도에서도 출전수 가중 기록률이 80% 미만이면 저파울 점수를 사용하지 않습니다. 기록이 없는 것을 무파울로 간주하지 않습니다.

## 2. 백분위와 결측값

유효 비교 표본 N, 자신의 값보다 작은 값의 개수 L, 같은 값의 개수 E(자신 포함)에 대해:

`백분위 = 100 × [L + (E − 1) / 2] / (N − 1)`

최솟값 0, 최댓값 100이며 동점은 평균 순위입니다. 전원 동점이면 50입니다. 숫자가 없거나 비교 표본이 4개 미만이면 `—`입니다. 파울률만 `100 − 백분위`를 사용하므로 낮은 파울률이 높은 CLEAN 점수가 됩니다.

가중식에서 결측 항목은 제외하고 남은 항목의 가중치 합이 1이 되도록 재배분합니다. 유효 항목이 하나도 없으면 축 전체가 결측입니다. 유형의 필수 축이 결측이면 그 유형은 탈락합니다. 이 방식은 자료가 적은 선수도 일부 유형을 가질 수 있게 하므로 결과와 함께 원자료·표본을 확인해야 합니다.

## 3. 선수 축의 정확한 계산식

아래 항목은 모두 위에서 구한 시즌 백분위입니다. SoccerBee 필드는 원본의 지표를 사용하며 PAC 등은 기존 능력치입니다.

| 기호 | 축 | 계산식 |
|---|---|---|
| S | SPEED | 최고속도 35% + 분당 스프린트(SPM) 20% + PAC 30% + 고강도 활동(HPM) 15% |
| W | WORK | 분당 이동거리(DPM) 35% + 에너지 20% + 참석률 25% + PHY 20% |
| A | ATTACK | 득점/경기 50% + SHO 30% + (득점+도움)/경기 20% |
| C | CREATION | 도움/경기 50% + PAS 30% + DRI 20% |
| P | POWER | PHY 45% + DEF 40% + DPM 15% |
| F | CLEAN | 100 − 파울/명시 기록 경기의 백분위 |
| D | DRIBBLING | DRI 백분위 |
| G | ATTACK POINTS | (득점+도움)/경기 백분위 |
| T | ATTENDANCE | 참석률 백분위 |

CHEMISTRY는 개인 특성이 아닌 실제 두 선수 조합의 별도 축입니다. 동행 경기수는 조합의 신뢰도와 동행비율에 반영합니다. 활동량이 많다고 파울이 많은 것에 가점을 주지는 않습니다.

## 4. 조합 점수

동행 경기 n은 두 선수가 같은 팀으로 유효 출전한 경기수입니다. 두 선수 전체 출전수를 각각 n₁, n₂라 하면:

`동행비율 = n / max(n₁, n₂)`

동행 5경기 이상인 서로 다른 조합을 비교 모집단으로 사용합니다. 최소 4조합이 필요합니다. 두 선수의 합산 득점률은 함께 출전한 경기에서의 합산 골 / n입니다.

기존 커플점수는 기준선수에 따라 달라지므로 `대칭 커플점수 = [기존 점수(A→B) + 기존 점수(B→A)] / 2`로 통일합니다. 기존 점수는 기존 `chemistry()` 계산 결과를 그대로 재사용합니다.

- **B** = 동행비율의 조합 백분위
- **K / CHEMISTRY** = 대칭 커플점수 백분위 50% + 실제 동행 승률 백분위 30% + B 20%
- **보정 승점률** = `100 × (승 + 0.5×무 + 2.5) / (n + 5)`
- **R / 동행 성적** = 보정 승점률 60% + 동행 합산 득점/경기 백분위 40%

보정 승점률은 가상의 5경기를 50% 승점률로 더해 적은 경기의 극단값을 완화합니다. 팝업에 표시하는 실제 승률은 보정하지 않은 `승 / n × 100`입니다.

## 5. 동질형·상보형·최종 점수

`H(x,y) = 0.6 × min(x,y) + 0.4 × (x+y)/2`

표의 `H(S)`는 두 선수의 S를 위 식에 넣는 뜻입니다. `H(0.7S+0.3W)`는 선수별 혼합 점수를 먼저 계산한 뒤 H를 적용합니다.

`X(L,R)`은 A의 L과 B의 R, B의 L과 A의 R을 각각 H로 계산하여 **각 역할의 필수 조건을 충족하는 배치 중 더 높은 값**을 선택합니다. 역할 점수가 같으면 첫 역할 선수명의 한글 정렬 순서를 사용합니다. 선택 순서를 바꿔도 결과가 같습니다.

`최종 점수 = 특성 점수 × 70% + R × 20% + K × 10%`

아래 20종의 필수 조건에 더해 **특성 점수 ≥65, 최종 점수 ≥65**를 모두 만족해야 후보가 됩니다. 점수는 판정 시 반올림하지 않고 화면에서 소수점 첫째 자리로 표시합니다.

## 6. 20종 판정표

‘두 선수’는 각각 조건을 만족해야 한다는 뜻입니다. 두 역할로 적힌 유형은 X 방식으로 역할을 바꾸어 평가합니다. 백분위 조건의 척도는 0~100이며 실제 승률·참석률 조건만 원자료 비율입니다.

| 순서 | 유형 | 특성 계산식 | 필수 조건 |
|---:|---|---|---|
| 1 | 폭주 듀오 | `H(0.7S+0.3W)` | 두 선수 S≥70, W≥55 |
| 2 | 속공 듀오 | `X(C, 0.6S+0.4A)` | 패서 C≥70 / 침투 S≥70, A≥60 |
| 3 | 쌍포 듀오 | `H(A)` | 두 선수 A≥70 |
| 4 | 메이커 & 킬러 | `X(C,A)` | 메이커 C≥70 / 해결사 A≥70 |
| 5 | 트윈 엔진 | `H(W)` | 두 선수 W≥70 |
| 6 | 철벽 듀오 | `H(0.65P+0.35F)` | 두 선수 P≥65, F≥60 · 파울 기록 충족 |
| 7 | 테크니션 듀오 | `H(0.6C+0.4D)` | 두 선수 C≥65, D≥65 |
| 8 | 압박 듀오 | `H(0.4W+0.35S+0.25P)` | 두 선수 W≥65, S≥60, P≥55 |
| 9 | 승리 듀오 | `H(0.5W+0.5P)` | 동행≥10, 실제 승률≥70% |
| 10 | 찰떡 듀오 | `0.6B+0.4H(W)` | 동행≥10, 기존 대칭 커플점수≥75, 동행비율≥50% |
| 11 | 메이커 듀오 | `H(C)` | 두 선수 C≥70 |
| 12 | 불도저 듀오 | `H(0.65P+0.35A)` | 두 선수 P≥70, A≥55 |
| 13 | 공격본능 듀오 | `H(G)` | 두 선수 G≥70 |
| 14 | 클린 듀오 | `H(0.5P+0.5F)` | 두 선수 F≥80, P≥50 · 파울 기록 충족 |
| 15 | 개근 듀오 | `H(T)` | 두 선수 실제 참석률≥85%, 동행≥10, 동행비율≥50% |
| 16 | 밸런스 듀오 | `min(H(S),H(A),H(C),H(W),H(P))` | 두 선수 S/A/C/W/P 모두≥55 |
| 17 | 택배와 침투 | `X(C,S)` | 패서 C≥75 / 러너 S≥75 |
| 18 | 수호자와 해결사 | `X(P,A)` | 수호자 P≥75 / 해결사 A≥75 |
| 19 | 에너지 공급 듀오 | `H(0.7W+0.3C)` | 두 선수 W≥75, C≥60 |
| 20 | 파괴 듀오 | `H(0.4S+0.4A+0.2P)` | 두 선수 S≥65, A≥65, P≥60 |

특성 점수가 동일하더라도 실제 성적 R과 CHEMISTRY K가 낮으면 최종 65점 문턱을 넘지 못할 수 있습니다. 개근 유형도 높은 실제 참석률만으로 자동 부여하지 않으며, 비교 집단 내 참석률 백분위가 충분해야 합니다.

## 7. Main·Sub와 신뢰도

- 동행 **0~4경기:** 분석중, 별명·최종점수 미표시.
- 동행 **5~9경기:** 조건을 만족하면 별명과 LOW CONFIDENCE 표시.
- 동행 **10경기 이상:** STANDARD 표시. 승리·찰떡·개근은 별도로 10경기 필수 조건이 있습니다.
- 선수·조합 백분위 표본이 부족하면 자료 부족 이유를 표시합니다.
- 조건을 충족하는 유형이 없으면 **뚜렷한 유형 없음**으로 표시합니다.
- 최고 최종점수가 Main입니다. 다음 후보 중 Main과 10점 이내인 최고점 유형 하나가 Sub입니다. 동점 우선순위는 위 표 순서입니다.
- STANDARD는 동행 경기수 기준이며 모델의 정확도나 전체 측정 자료의 완전성을 보증하는 문구가 아닙니다.

## 8. 팝업 UI

1. **CHEMISTRY MAP 연결선 클릭·터치 또는 키보드 Enter/Space**로 엽니다. 보이지 않는 넓은 선 클릭 영역을 두어 선택을 쉽게 했습니다. 선수 노드 선택 동작은 기존처럼 기준선수를 변경합니다.
2. 상단: 유형명, 두 선수 이름, 선택 연도·대회, Main 점수, 신뢰도, Sub 유형.
3. 남색 요약줄: 실제 동행 경기수, 승·무·패, 실제 승률, 합산 골, 동행비율, 대칭 커플점수.
4. 본문 왼쪽: 5각형 **DUO DNA — SPEED / ATTACK / CREATION / WORK / CHEMISTRY**. 앞의 네 축은 H, 마지막 축은 K입니다. 수치도 함께 제공합니다. 결측은 ‘—’이며 그림에서는 중심점으로 표시합니다.
5. 본문 오른쪽: **WHY THIS DUO?**. 필수 조건, 해당 선수별 지표, 상보형 역할, 특성·성적·케미스트리 점수 기여를 표시합니다.
6. 하단: 선수별 축과 참석률, 펼쳐 볼 수 있는 시즌 원자료·표본, 20종 계산식·조건표.
7. PC에서는 그래프와 설명을 2열, 모바일에서는 1열로 배치합니다. 팝업 내부를 세로로 스크롤하고 긴 기준표는 좌우로 이동합니다.
8. 닫기 버튼·Escape·팝업 바깥 클릭으로 닫고 이전 포커스로 돌아갑니다. 지도 드래그 직후 클릭을 억제해 이동 동작이 팝업을 열지 않도록 합니다.

예를 들어 SPEED가 한 명만 높으면 폭주 조건을 통과하지 못합니다. 반면 한 명의 CREATION과 다른 선수의 SPEED·ATTACK이 충분하면 속공 후보가 됩니다. 더 높은 다른 후보가 있으면 그것이 Main이 되므로 속공 조건을 만족했다고 항상 속공이 Main인 것은 아닙니다.

## 9. 검증 범위

로컬 Chromium의 PC 1440px·모바일 390px에서 20종 조건 도달, 백분위 양끝·동점·표본 부족, 선수 순서 대칭성, 5경기 미만 보류, 미측정 SoccerBee·미기록 파울, 조회일 이후 측정 제외, 중복·양 팀 등록, 실제 동행 성적, DB 불변, 팝업·키보드·지도 드래그 및 기존 기능 회귀를 검사했습니다. 조건 만족과 미충족 팝업을 모두 확인했습니다.

검증은 샘플·합성 기록을 사용했고 외부 서버 요청을 차단했습니다. 실제 휴대폰 실기기 검사, 운영 DB 전체의 유형 분포 보정, 운영 배포는 수행하지 않았습니다.
